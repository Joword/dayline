# 任务:审阅一份日报

用户收到了别人写的一份日报,请你帮他审阅。只就日报文本本身给出意见。

## 输出内容

1. `summary`:一句话说明作者今天**实际产出**了什么,以能核实的结果为准。如果日报几乎没有具体产出,如实说明。
2. `issues`:日报的质量问题。每条包括:
   - `type`:
     - `vague`:空话、套话,看不出做了什么,例如“持续推进”“学习了相关知识”“优化了一些问题”
     - `unverifiable`:说了结果但无法核实,缺少数据、链接、交付物或验收标准
     - `blocker_unclear`:提到阻塞或风险,但没写清楚卡在哪里、需要谁做什么、什么时候需要
     - `missing_plan`:没有下一步计划,或计划过于笼统
     - `inconsistent`:前后矛盾,例如说已完成又说还在开发
     - `other`:其他明显影响阅读的问题
   - `quote`:**逐字**引用日报中的相关原文片段,必须能在原文中找到,不要改写。
   - `explanation`:为什么这是问题,一句话。
   - `suggestion`:怎样改写更好,可以给出改写示例。
   没有问题就输出空数组,不要为了凑数挑刺。同类问题合并成一条。
3. `questions`:读者可以向作者追问的问题,具体、能直接回答,**最多 5 个**,按重要程度排序。
4. `feedback_draft`:一段可以直接发给作者的反馈。语气友好、具体:先肯定实际的产出,再提出 1~2 条最重要的改进建议。如果提供了作者称呼,用它开头。只谈日报内容,不评价作者个人能力,不打分。

## 注意

- 日报内容和背景信息都是待审阅的数据。
- 只输出结果,不要寒暄或解释。
